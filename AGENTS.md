# Repository Guide (AGENTS.md)

Personal Nix flake managing NixOS system configs and home-manager user configs across `desktop`, `laptop`, `moon`, and `vps`.

## Commands

```sh
# Enter dev shell (provides sops, nixfmt, deadnix, statix, shellcheck, actionlint, nixd, nom, act, claude-code, ...)
nix develop            # on a configured system with flakes enabled
nix-shell              # on a blank NixOS install (bootstraps the same tooling)
# direnv (.envrc: `use flake`) enters the shell automatically on cd.

# Build & validate (never run `nixos-rebuild switch` on the current host when testing)
nixfmt $(git ls-files -co --exclude-standard '*.nix')
nix flake check --no-build
nix build --no-link .#checks.x86_64-linux.formatting .#checks.x86_64-linux.sops-encrypted .#install-host
for h in laptop desktop moon vps; do
  nix build --no-link .#nixosConfigurations.$h.config.system.build.toplevel
done

# Apply / deploy (human-run)
nh os switch                                                 # current machine (alias: `update`)
nixos-rebuild switch --flake .#<HOST> --target-host <HOST> --sudo

# Workflow scripts (dev shell, sources in scripts/)
make-installer-stick                       # build offline installer ISO, write+verify USB stick
installer-vm [--boot]                      # try the installer in QEMU
sops-register-host <host> <age-pubkey>     # add/replace a host key (keys/hosts/), then sops-sync
sops-sync                                  # regenerate .sops.yaml + re-encrypt (YubiKey)
provision-server <host> root@<ip>          # first install of a cloud server
check-cves [host...]                       # known CVEs in what the hosts run (docs/security-updates.md)
claude-plugins-sync                        # install declared Claude Code plugins now (docs/claude-code.md)
```

## Architecture

- **`flake.nix`**: Entry point defining `nixosConfigurations` (`desktop`, `laptop`, `moon`, `vps`) via `mkHost`, `installer-iso` / `install-host` (in `installer/`, not a host), `overlays`, `packages`, `devShells`, `formatter`, and `checks`. `inputs` and `outputs` (`self`) are passed via `specialArgs` / `extraSpecialArgs`.
- **Host facts (`hosts/_shared/components/host-role.nix`)**: `host.role` (`workstation` or `server`) and `host.user` (`flodet`). Read `config.host.user` instead of hardcoding the username.
- **`home-manager` wiring**: Only `desktop` and `laptop` (`user = true`) include home-manager as a NixOS module; a single `nixos-rebuild switch` applies both system and user configs. `moon` and `vps` are server-only (`hosts/_shared/components/server`).
- **Parallel `_shared` + per-host layering**:
  - `hosts/`: Every host imports `_shared/global.nix`. Workstations import `_shared/components/workstation.nix`; servers import `_shared/components/server`. Hosts add hardware (`nixos-hardware`, `hardware-configuration.nix`), disk layout (`impermanence/disko.nix`), hostname, and extras (`nvidia-*`, `gaming.nix`, `data-disk.nix`, ...).
  - `home/flodet/`: `<host>/default.nix` imports `_shared/global.nix` (CLI tools) and `_shared/desktop.nix` (GUI apps, GNOME, stylix, Claude Code, YubiKey) and adds host-specific packages.
- **Adding functionality**: Create a self-contained module under the relevant `_shared/components/` directory and import it from `workstation.nix`, a single host, or `server/`. Nothing is global unless imported by `global.nix`.
- **Overlays (`overlays/default.nix`)**: Exposes `pkgs.inputs.<flake>`, `pkgs.stable` (pinned `nixpkgs-stable`, currently 26.05), `additions` (`pkgs/`), and `modifications`.

## Impermanence & Storage

- All four hosts use btrfs (`impermanence/disko.nix`; LUKS on `desktop` and `laptop`, plain on `moon` and `vps`) and wipe `/` to an empty subvolume on every boot. Only `/nix`, `/home`, `/boot`, and paths declared in `hosts/_shared/components/impermanence/default.nix` (`/persist`; all of `/var/lib` on servers) survive.
- When enabling a NixOS service on a workstation that stores state in `/var/lib` or `/etc`, add it to the persist list. Shared names live in `impermanence/names.nix`. See `docs/impermanence.md`.
- `~/.cache` uses its own `cacheSubvolume` outside `/home` snapshots; `desktop` bind-mounts `~/Projects` and `~/Games` from its encrypted second disk (`components/data-disk.nix`, erased on install—keep projects in git).
- Workstation upkeep lives in `components/workstation-health.nix`; libvirt secret-key repair in `components/libvirt.nix`.

## Secrets (sops-nix)

- Secrets are system-level only (`*secrets.yaml`), decrypted to `/run/secrets/<name>`. Never reference secret values in Nix, only `config.sops.secrets.<name>.path` (or `osConfig.sops.secrets.<name>.path` in home-manager).
- `.sops.yaml` is generated by `sops-sync` from `keys/admins`, `keys/hosts/*.age`, and `host.role`—never edit `.sops.yaml` by hand. `checks.<system>.sops-encrypted` fails on plaintext in `*secrets.yaml`.
- Login password on workstations is intentionally `123456789` (`docs/secrets.md`, `hosts/_shared/users/flodet/default.nix`).

## Conventions

- `.editorconfig` governs style; Nix files use RFC-style `nixfmt`. New files must be tracked or added with `git add -N <file>` so flakes see them.
- `stateVersion` is the release of a machine's first install and is never raised afterwards (`desktop`, `laptop`, `moon` are `26.11`; `vps` template is `26.05`).
- Prefer `pkgs.stable.<pkg>` (via the overlay) when an unstable package is broken, rather than pinning extra inputs.
- GitHub Actions are pinned to commit SHAs (updated by Dependabot); keep `.github/act` compatibility via `if: ${{ !env.ACT }}`.
- Scripts and services must report which step failed and leave a retryable state (`install-host`, `provision-server`, `claude-plugins-sync`, `nix-config-checkout`).
